# 108 — Spike: V4L2 capture of the real cards (WSL via usbipd, then real Linux)

**Status:** in-progress
**Phase:** Phase 10: Linux
**Depends on:** 106, 109
**Complexity:** critical — suggested model: Claude Code → opus / fable · Codex → sol

## Objective

Capture from the UGREEN-25854 (and the MS2131 when available) with raw V4L2 from C#. Write the Linux device inventory, fill the error table, and answer the central WSL question: does 1080p60 MJPEG survive usbip?

## Relevant files / modules

- `docs/research/linux.md` — research (2026-10-23)
- `docs/research/linux.md` §2 and §7c
- `docs/research/devices/ugreen-25854.json`, `ugreen-25854-windows.json`, `ugreen-hdmi-capture-ms2131.json` — the shape the Linux JSON must match
- `Apps/Windows/src/HDMICaptain.Media` — `MfSource` and the inventory mode, as patterns
- Linux UAPI `videodev2.h` (struct layouts for P/Invoke)

## Steps

1. `V4l2Device` P/Invoke: open with `O_RDWR|O_NONBLOCK`, `QUERYCAP`, `ENUM_FMT/FRAMESIZES/FRAMEINTERVALS`, `S_FMT`, `S_PARM`, `REQBUFS(MMAP, 4+)`, `QUERYBUF` + `mmap`, `QBUF/DQBUF`, `STREAMON/OFF`, `poll`. Struct layouts checked against `videodev2.h` with a `sizeof` test from a tiny C helper.
2. `--inventory` mode writes `docs/research/devices/ugreen-25854-linux.json` (and `-ms2131-linux.json` later): nodes, formats and intervals, VID:PID, serial, bus_info and the sysfs link speed.
3. `V4l2Source`: a capture thread, newest-frame-wins, dropping `bytesused == 0` and `V4L2_BUF_FLAG_ERROR`, with timestamps for fps/drops. Raw MJPEG frames are saved to a file for 110's benchmark.
4. WSL first: **ask the user before `usbipd attach`**, because it takes the card from the running Windows app. Measure fps, drops and corrupt frames for 60 s at 1080p60 MJPEG and at the card's other modes. Log `dmesg` vhci errors.
5. Fill the error table in `linux.md` §2c: unplug (or `usbipd detach`), a second opener (`v4l2-ctl --stream-mmap` while we stream), HDMI source pulled.
6. If usbip can't stream reliably, record the evidence, set the live-capture half of this task `blocked` on a real Linux install (124's machine), and keep WSL for everything else.

## Acceptance criteria

- [ ] The Linux inventory JSON for the UGREEN-25854 is committed
- [ ] A 60 s 1080p60 measurement over usbip is logged (fps, drops, corrupt frames), with a go/no-go verdict for live capture in WSL
- [ ] The `linux.md` §2c rows for unplug/detach and a second opener are filled with the observed errno/flags
- [ ] The task stays `in-progress` (not `done`) until the same 60 s measurement has run on real Linux or the user waives it
