# 047 — Hover control bar

**Status:** in-progress
**Phase:** Phase 7: Viewer features (free)
**Depends on:** 033, 043
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

A floating bottom-centre control bar that appears when the cursor is near the bottom edge of a viewer window (inspired by the macOS ⇧⌘5 toolbar, Recordly, Screen Studio — not a copy). Puts the most-used actions on the picture: input/profile switching, volume/mute, screenshot, Save Recent, Go Live, Record, view options, full screen. We always record the full HDMI feed — no display/window/area modes.

The bar must never appear in recordings, Save Recent clips, streams or screenshots: those read `CaptureEngine` sinks / `MetalRenderer.currentFrame`, and SwiftUI overlays are composited by the window server afterwards.

## Steps

1. Reveal logic: bottom zone = max(110 pt, 25 % of height); hide 2 s after leaving; stay while hovered or a menu is open; no cursor hide while visible.
2. Bar groups: Input ▾ | Sound | Screenshot, Save Recent ▾ | Go Live, Record | ⋯ Options, Full screen.
3. Responsive: labels ≥ 620 pt, icons only 380–620 pt, minimal below 380 pt.
4. Pro buttons show a lock and route through `EntitlementStore.gate`.
5. Pref + Settings → Window toggle; DEBUG `-qaAction controls` pins it visible.

## Acceptance criteria

- [ ] Bar appears only near the bottom edge, hides ~2 s after leaving, never while hovered/menu open
- [ ] Works in windowed, full screen and clean mode; not shown in Multi-View tiles
- [ ] All controls perform the same action as their menu-bar equivalents
- [ ] Three width classes render without clipping
- [ ] A frame extracted from a recording / Save Recent clip / received stream made while the bar was pinned shows no bar
- [ ] Free users see lock badges; clicking opens the upgrade sheet
