# 060 — App icon (Mac + iPad) via Codex image generation

**Status:** done
**Phase:** Phase 9: Polish & launch readiness
**Depends on:** none
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

Give HDMI Captain a real icon on both platforms. Generate concepts with Codex's image generation, let the user pick one, and produce the final asset catalog entries. The icon has to read at 16 px (Mac menus) and on the iPad home screen.

## Relevant files / modules

- `project.yml` — add `Apps/Shared/Assets.xcassets` (or one per platform) to both targets; `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon`
- `docs/spec.md` §1 — product identity (HDMI capture viewer, "captain")
- Codex CLI (`~/.local/bin/codex exec`). The codex-image plugin's `--full-auto` call is broken on 0.153, so call it directly: `codex exec -s workspace-write --skip-git-repo-check -C <dir> "Use the imagegen skill … save to <path>"` for images, and `codex exec -s read-only -i shot.png "…"` for design review
- `sips` / `iconutil` for resizing; the macOS icon follows the rounded-rect grid, iOS uses a single 1024 px square

## Steps

1. Brief: an HDMI connector or capture card plus a captain or helm cue, readable at small sizes, no text, works on light and dark. Get 3–4 distinct concepts from Codex (1024×1024).
2. Show the concepts to the user and record their pick in the log.
3. Refine the chosen concept: a macOS variant on Apple's icon grid with a shadow and transparent corners, and an iOS full-bleed square with no transparency.
4. Generate all sizes into `AppIcon.appiconset` (Mac 16–1024 @1x/@2x; iOS 1024 single size) and wire them into both targets.
5. Check the icon at real sizes: Dock, Finder list (16 px), iPad home screen, Settings.

## Acceptance criteria

- [x] Both apps build with the new icon and no asset-catalog warnings
- [x] A 16 px render is still recognisable (screenshot in the log)
- [x] The user picked the concept (logged)
