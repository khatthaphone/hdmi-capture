## Objective

Prove live capture from both UGREEN cards through `IMFSourceReader`, record their real Windows formats, and pin down the error codes the controller will map.

## Relevant files / modules

- `docs/spec.md` §13 — Windows requirements
- `docs/research/windows.md` — research (2026-10-22)
- `docs/research/windows.md` §2
- `docs/research/devices/*.json` — Mac inventories to compare against
- `tools/device-inventory/` — Mac CLI whose JSON shape to reuse

## Steps

1. Enumerate VIDCAP sources; dump every native type (subtype, size, frame rates) plus symbolic link, VID:PID, serial, ContainerId and USB link speed. Do this from a `--inventory` mode of the app (or a small console project) that writes `docs/research/devices/<card>-windows.json`.
2. Async Source Reader with `MF_LOW_LATENCY`, `MF_READWRITE_DISABLE_CONVERTERS`, one outstanding `ReadSample`. Set the chosen native type directly; upload YUY2/NV12 into the 088 renderer (MJPEG waits for 090).
3. Hot-plug with `CM_Register_Notification`; log what each event and `OnEvent` HRESULT looks like for: unplug mid-stream, a second app (Windows Camera) holding the card, camera privacy off, sleep/resume. Check the hex values against `mferror.h` (SDK 26100).
4. Check the Windows 11 "Allow multiple apps to use camera" setting: which type we get while it's on.
5. Record the observed fps and dropped frames (sample timestamps) for each format.
