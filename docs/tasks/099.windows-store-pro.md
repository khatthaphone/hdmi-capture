## Objective

The `EntitlementStore` equivalent on the Microsoft Store: one durable add-on, one gate, and a fake for development, because the Store has no sandbox.

## Steps

1. `IProStore` with `StoreProStore` (`StoreContext.GetDefault()`, `InitializeWithWindow.Initialize(ctx, hwnd)`, `GetAppLicenseAsync().AddOnLicenses` on launch, `RequestPurchaseAsync` on the UI thread) and `FakeProStore` (DEBUG, `-debugUnlockPro YES`, a dev toggle).
2. Cache the entitlement locally (DPAPI-protected); re-verify on launch and when back online; never lock out an owner offline.
3. One gate (`ProGate.Require(ProFeature)`) used by Record and Save Recent only; free features never check it.
4. Upgrade dialog with the same copy and layout as `UpgradeView` (064); restore = re-query the licence.
5. Unit tests for the gate and cache with the fake; document in this log the Partner Center steps needed for real-purchase testing (hidden app, add-on, install from the Store once).

## Acceptance criteria

- [ ] Fake store: locked → upgrade dialog → unlocked → Record enabled, with no restart
- [ ] Free features work with the Store unavailable (unpackaged Debug)
- [ ] Real-purchase test steps written down for 103
