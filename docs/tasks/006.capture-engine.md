## Objective

Owns the AVCaptureSession: configures input/outputs on a serial queue, applies the selected format, and delivers sample buffers to consumers with minimal latency. Core of the app; mistakes here cause latency or crashes.

## Relevant files / modules

- `Packages/CaptureCore/Sources/CaptureCore/CaptureEngine.swift` — new
- `DeviceCatalog.swift / FormatSelector.swift` — inputs
- `docs/spec.md` — authoritative product/technical spec

## Steps

1. Serial `sessionQueue`; all configuration inside `beginConfiguration/commitConfiguration`.
2. Video: `AVCaptureDeviceInput` + `AVCaptureVideoDataOutput` (`alwaysDiscardsLateVideoFrames = true`, `420v`), delegate on a dedicated high-QoS queue.
3. Apply format via `lockForConfiguration`, set `activeFormat`, `activeVideoMin/MaxFrameDuration`.
4. Expose `CaptureState` enum (`.idle, .permissionNeeded, .scanning, .connecting, .live(format), .signalLost, .failed(Error)`) observable on main actor.
5. Frame delivery: a `FrameSink` protocol (renderer, later recorder/compositor) — fan out without copying.
6. Handle camera/mic permission via `AVCaptureDevice.requestAccess`.
7. Switching device/format while live must not leak sessions or deadlock.

## Acceptance criteria

- [ ] App shows frames from a real dongle via a debug sink (frame counter logs ~fps)
- [ ] Switching device 20× rapidly: no crash, no leaked sessions (Instruments Leaks clean)
- [ ] Permission denied → `.permissionNeeded` state
- [ ] Unplug while live → `.signalLost` or `.scanning`, no crash
