## Objective

Play the card's HDMI audio through the default output with flat latency, reusing the C# audio DSP from Windows. Decide the Linux audio backend: the Pulse API everywhere, or ALSA capture + Pulse playback.

## Steps

1. Small P/Invoke layer over `libpulse` (threaded mainloop, `pa_stream` record + playback, small `tlength`/`fragsize`) and over `libasound` (`snd_pcm` hw capture), behind one capture interface.
2. Pairing: find the ALSA card whose USB parent matches the V4L2 node (sysfs), then its Pulse source if a server owns it.
3. `LinuxAudioPipeline` uses the shared ring/drift/resampler/channel/meter code, with the target from `DriftController.MinimumTargetMs(packet, period)`.
4. WSL: ALSA capture of the usbip card + playback to WSLg's Pulse. Note the RDP latency but don't tune to it. Real Linux: Pulse (pipewire-pulse) for both, then compare latency and underflows against ALSA capture.
5. Write the backend decision and numbers in `linux.md` §4.

## Acceptance criteria

- [ ] HDMI audio is audible from the card through the default output (WSL or real Linux), with the meters moving
- [ ] A 10-min run logs a flat buffer and no underflows on at least one real-Linux configuration (or the WSL result is logged and the real-Linux part is left open in the log)
- [ ] The backend choice is written down with the measurements
