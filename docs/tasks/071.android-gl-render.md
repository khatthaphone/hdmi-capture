## Objective

Native EGL/GLES 3 renderer drawing into a Compose `AndroidExternalSurface`, fed by a native `TestPatternSource`, so the display path is proven (and measurable) before any USB work. Also the emulator/CI video source.

## Relevant files / modules

- `docs/spec.md` §12 — Android requirements
- `docs/research/android.md` — research
- `Packages/CaptureCore/Sources/CaptureCore/MetalRenderer.swift` — shader maths, scale modes, ranges to match
- `TestPattern.swift` — patterns to reproduce
- `docs/research/android.md` §4

## Steps

1. `core:render` NDK: render thread owning EGL; `ANativeWindow` from the Compose surface; NV12, YUY2 and planar 4:2:2/4:2:0 inputs; BT.601/709 × limited/full; fit/fill/stretch/integer; linear/nearest.
2. Native `TestPatternSource` (SMPTE bars, full bars, grid, gray ramp) writing into the same frame ring a capture source will use.
3. `feature:viewer` minimal screen with the surface; DEBUG intent extra `testPattern`.
4. `Surface.setFrameRate`; draw on arrival; Perfetto trace sections.
5. Screenshot from the GL framebuffer (not the window) to prove overlays stay out.

## Acceptance criteria

- [ ] Emulator shows each test pattern correctly (screenshot saved in `docs/research/android/`)
- [ ] Rotation/resize doesn't recreate the renderer or restart the source (log)
- [ ] No per-frame Kotlin allocation in a Perfetto/allocation capture
