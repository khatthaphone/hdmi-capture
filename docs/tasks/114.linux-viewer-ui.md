## Objective

The main libadwaita viewer: the same status screens and copy as the other apps, a hover control bar over the video, the right-click menu, full screen and clean mode, Wayland-correct window behaviour, keyboard shortcuts and accessibility.

## Relevant files / modules

- `docs/spec.md` §14 — Linux requirements

- `Apps/Windows/src/HDMICaptain.App/MainWindow.xaml(.cs)` (task 094) — structure, `-qaPhase` screens, mic badge
- `Apps/Shared/ContentView.swift`, `ControlBar.swift` — the original design
- GNOME HIG: https://developer.gnome.org/hig/

## Steps

1. `Gtk.Overlay` with the GLArea underneath and the status pages (`Adw.StatusPage`), control bar and badges on top. Overlays never touch the pass-1 output.
2. Every status from `CaptureState` (welcome, scanning, permission, connecting, waiting, no signal, black, reconnecting, disconnected, in use, sleep, failed, audio-missing badge) and `-qaPhase <name>` for screenshots.
3. Hover control bar (auto-hide, `-qaPinControls`), right-click `Gtk.PopoverMenu`, double-click full screen, cursor auto-hide after 3 s, clean mode (no decorations), window size presets. Letterbox on resize. Always on top through X11 only, with an explanatory menu item on Wayland.
4. Shortcuts per spec §14.7 via `Gtk.ShortcutController`, plus a shortcuts window (`Gtk.ShortcutsWindow`).
5. Accessibility: accessible names and roles on every control; Tab order; check with Accerciser or `GTK_DEBUG=interactive`. Follow the high-contrast style.
6. DEBUG `-qaAction` subset: screenshot, copy, size50, actualPixels, fullScreen, settings.

## Acceptance criteria

- [ ] Each `-qaPhase` screen renders correctly in WSLg (screenshots checked, then deleted)
- [ ] Control bar, menu, full screen, clean mode and shortcuts work on WSLg and on a real GNOME Wayland session (the latter can be logged in 124)
- [ ] Every interactive control has an accessible name (automated check walks the widget tree)
