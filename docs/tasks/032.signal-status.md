# 032 — Signal status: no-signal/HDCP detection, hold last frame, requested vs actual

**Status:** done
**Phase:** Phase 7: Viewer features (free)
**Depends on:** 010
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

Tell users what is actually happening on the wire (gaps #3 and #6): detect no-signal/HDCP black or vendor 'no signal' screens, keep the last good frame through short dropouts, and show requested vs delivered mode.

## Relevant files / modules

- `Packages/CaptureCore/Sources/CaptureCore/SignalAnalyzer.swift` — new, pure analysis of downsampled Y/CbCr stats
- `Packages/CaptureCore/Sources/CaptureCore/MetalRenderer.swift` — already exposes lastFrameSize; add hold-last-frame flag
- `Apps/macOS/Sources/ContentView.swift` — banner vs full overlay; stats shows requested vs actual
- `Packages/CaptureCore/Sources/CaptureCore/CaptureEngine.swift` — stall watchdog (3 s) to coordinate with banner
- `docs/spec.md` — authoritative product/technical spec (§10 business model, §11 feature expansion)

## Steps

1. Every ~10th frame, sample a 64×36 grid of luma/chroma on the capture queue (cheap CPU read) → SignalAnalyzer → .ok / .black / .solidColor(rgb).
2. Black for > 1 s → overlay 'No signal or HDCP-protected source' with hint (HDCP can't be captured; disable HDCP on PS/Apple TV).
3. Dropout < 3 s: keep last frame, show small 'Signal interrupted' banner instead of full overlay.
4. Stats overlay + Settings show requested format vs actual buffer size/pixel format; warn on mismatch.
5. Unit tests with synthetic pixel buffers (black, blue screen, color bars, noise).

## Acceptance criteria

- [x] SignalAnalyzer tests pass for black, solid blue, bars, noise
- [x] Turning the source off shows the no-signal message within 2 s; turning it on clears it
- [x] Brief unplug of HDMI (< 3 s) shows banner over last frame, not the full overlay
- [x] Stats show 'requested 1280×720 · actual 1280×720'
