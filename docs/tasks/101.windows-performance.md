# 101 — Windows performance & always-on pass

**Status:** in-progress
**Phase:** Phase 6: Windows
**Depends on:** 094
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

Make the app meet spec §13.10 under real conditions: no frame-path allocations, the right GPU, fast start, and no throttling.

## Relevant files / modules

- `docs/spec.md` §13 — Windows requirements
- `docs/research/windows.md` — research (2026-10-22)
- spec §13.10
- Task 083 (Android performance pass) — checklist to mirror

## Steps

1. Profile with dotnet-counters / PerfView: zero GC allocations per frame while live; `GCSettings.LatencyMode = SustainedLowLatency` while live.
2. Hybrid GPU: verify device on the display's adapter, cross-adapter moves, laptops on battery (EcoQoS opt-out verified in Task Manager).
3. Startup: ReadyToRun; try Native AOT + trimming and keep it only if warnings are clean and nothing breaks; measure cold start to first frame.
4. ETW events (EventSource) for capture, decode, render and present, viewable in WPA; document how to record a trace in CLAUDE.md.

## Acceptance criteria

- [ ] Cold start → live picture < 1 s on this PC with a card plugged in
- [ ] 0 allocations per frame in steady state (dotnet-counters log)
- [ ] The decision on AOT vs ReadyToRun recorded in the ADR
