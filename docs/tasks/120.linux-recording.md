# 120 — Linux recording & Save Recent (Pro)

**Status:** in-progress
**Phase:** Phase 10: Linux
**Depends on:** 111, 119
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

Record the clean source with audio to fragmented MP4, and keep a Save Recent ring, using hardware H.264 where available.

## Relevant files / modules

- `docs/spec.md` §14 — Linux requirements
- `docs/research/linux.md` — research (2026-10-23)
- `Apps/Windows` task 100 (Sink Writer recorder, rolling recorder) — the behaviour to match
- `docs/research/linux.md` §5
- FFmpeg licensing: build LGPL only (no `--enable-gpl`, no x264)

## Steps

1. Decide between bundling our LGPL FFmpeg (`libavcodec/avformat`, `h264_vaapi`, `h264_nvenc` via ffnvcodec, OpenH264, `aac`) and the Flatpak `ffmpeg-full` extension; log why.
2. P/Invoke recorder: encode pass-1 frames (GPU readback or NV12 conversion pass) + audio from the pipeline → fMP4 in `$(xdg-user-dir VIDEOS)/HDMI Captain`. Encoder probe order: VA-API → NVENC → OpenH264.
3. Save Recent: encoded ring trimmed at keyframes, remuxed on save (`-qaAction recent15`).
4. Recording is blocked on test patterns, as on Windows.
5. Inhibit suspend while recording.

## Acceptance criteria

- [x] A 3 s recording (`-qaAction record3s`) plays in ffprobe/ffplay with H.264 + AAC, the right duration and no UI in the frame
- [ ] `recent15` saves ~15 s with A/V in sync
- [ ] A 10-min recording with a clap test is in sync (can be logged under 124)
