# 077 — Capture controller: catalog, permissions, always-on recovery, lifecycle

**Status:** in-progress
**Phase:** Phase 5: Android
**Depends on:** 027, 070
**Complexity:** critical — suggested model: Claude Code → opus/fable · Codex → sol

## Objective

The Android `CaptureEngine`: one control thread that owns discovery, the permission sequence, source selection and recovery, honouring spec §12.2/§12.5.

## Relevant files / modules

- `docs/spec.md` §12 — Android requirements
- `docs/research/android.md` — research
- `Packages/CaptureCore/Sources/CaptureCore/CaptureEngine.swift`, `DeviceCatalog.swift`
- `Apps/Shared/AppModel.swift` — policy to mirror
- `docs/adr/0002-android-stack.md`

## Steps

1. `UsbDeviceCatalog` (attach/detach, stable key, audio pairing); `CaptureController` on a single-thread dispatcher driving `RecoveryMachine` (070).
2. Permission flow: welcome card → CAMERA/RECORD_AUDIO → USB grant; privacy-toggle detection; states for each.
3. Lifecycle: capture tied to STARTED; `configChanges` handled; PiP/split screen keep running; camera-priority loss → recovering.
4. Robolectric tests for the flows with fake sources (ShadowUsbManager).

## Acceptance criteria

- [ ] Rotation/resize/split screen/PiP don't restart capture (log)
- [ ] Unplug/replug and background/return recover without user action
- [x] Tests cover permission denied, privacy toggle, unplug mid-stream
