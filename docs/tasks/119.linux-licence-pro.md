# 119 — Pro on Linux: licence-key unlock + upgrade dialog

**Status:** blocked
**Phase:** Phase 10: Linux
**Depends on:** 114
**Complexity:** critical — suggested model: Claude Code → opus / fable · Codex → sol

## Objective

Pro (recording, Save Recent) unlocks with a licence key bought outside the store, behind the one shared gate. The vendor is the user's decision.

## Relevant files / modules

- `docs/spec.md` §14 — Linux requirements
- `docs/research/linux.md` — research (2026-10-23)
- `docs/adr/0004-monetization.md` — needs a Linux section
- `Apps/Windows/src/HDMICaptain.Core/ProEntitlement.cs`, `ProFeature.cs`; Windows `ProStore` (task 099)
- Lemon Squeezy License API: https://docs.lemonsqueezy.com/api/license-api
- Flathub requirements on paid unlocks: https://docs.flathub.org/docs/for-app-authors/requirements

## Steps

1. **Ask the user** to choose the vendor (Lemon Squeezy, or Paddle + Keygen, or other) and the price. Record it in ADR 0004. Until then, build against an `ILicenceService` with a fake implementation and set this task `blocked` on the decision once the rest is done.
2. Activate (key → instance id), validate on launch and periodically, cache the signed result in `$XDG_DATA_HOME/hdmicaptain/` for offline use with a grace period. Deactivate from settings.
3. Upgrade dialog (`Adw.AlertDialog`/window) with the same copy as other platforms, a buy link (opens the browser) and a key field.
4. One gate equivalent to `EntitlementStore.gate`; free features never check it. DEBUG `-debugUnlockPro YES`.
5. No secrets in the binary beyond the vendor's public validation key.

## Acceptance criteria

- [x] The gate blocks recording and Save Recent without a licence and allows them with one (tests with the fake service)
- [x] Offline launch with a cached licence keeps Pro; an invalid or revoked key drops it on the next validation (tests)
- [x] The vendor decision is in ADR 0004, or the task is `blocked` on it with the question surfaced to the user
