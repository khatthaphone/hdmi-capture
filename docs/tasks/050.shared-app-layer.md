## Objective

Move platform-neutral app code out of `Apps/macOS/Sources` into `Apps/Shared/`, compiled into both app targets, so the iPad target reuses the models, Pro store and views instead of forking them. A 2026-10-21 survey found these files have no AppKit references: `DeviceSession`, `ViewerPrefs`, `EntitlementStore`, `UpgradeView`, `Symbols`, `ScopesPanel` and `StreamSettings`. `ViewerModel` (21 AppKit refs: NSWindow, NSMenu tracking, NSPasteboard, full screen) must be split.

## Relevant files / modules

- `Apps/macOS/Sources/Model/ViewerModel.swift` — split it: the shared core (preset, live info, recording, controls state) in Shared, and an NSWindow/NSMenu/NSPasteboard extension in macOS
- `Apps/macOS/Sources/AppModel.swift` — orchestration; keep the macOS window and menu policy separate
- `Apps/macOS/Sources/ControlBar.swift` — mostly SwiftUI; leave it in macOS for now (055 adapts it)
- `project.yml` — add `Apps/Shared` to the macOS target's sources

## Steps

1. Create `Apps/Shared/` and `git mv` the AppKit-free files, so history is kept.
2. Split `ViewerModel` along the platform line: move window, menu and pasteboard code into `ViewerModel+macOS.swift`, and put a small protocol or closures where the shared core needs a platform action (copy image, toggle full screen).
3. Do the same for anything in `AppModel` the iPad will need (device selection, presets, Pro gating). Leave window and menu-bar-extra code in macOS.
4. Update `CLAUDE.md` → Layout.
5. Smoke test on the Mac: run with `-testPattern smpteBars -qaPinControls YES` and check the `-qaAction screenshot`/`record3s` paths.

## Acceptance criteria

- [ ] `Apps/Shared/` holds no `import AppKit` and no `NS*` types (`grep -rE 'AppKit|\bNS[A-Z]' Apps/Shared` returns nothing except NSObject/NSLock-style Foundation types)
- [ ] `make build`, `make test` and `make test-app` pass
- [ ] The macOS app behaves the same: control bar, menus, screenshot and record still work (checked with the QA launch arguments)
