## Objective

Move the Android GLES 3 renderer to a platform-neutral `native/render-gles/` library used by both Android and Linux. On Linux, draw test patterns in a `GtkGLArea` through a C ABI called from C#. The renderer stays one codebase for both platforms.

## Steps

1. Split out the platform parts: logging, tracing/performance hints, and the window/surface (ANativeWindow + EGL surface on Android; render into the framebuffer GTK binds on Linux). Keep `render_jni.cpp` and the Android CMake building from the new location. If the Android build can't run on this PC, keep Android on its current files and fork, logging why, so the Android app isn't broken blind.
2. Linux C ABI (`hc_renderer_create/destroy/set_frame/render/set_options/read_pass1`) built by CMake into `libhcrender.so`, copied next to the app. C# P/Invoke in `HDMICaptain.Linux.Media`.
3. `GtkGLArea` set to GLES 3.0+ (`SetAllowedApis(GLES)`, `SetRequiredVersion(3,0)`), `OnRealize` creates the renderer, `OnRender` draws, and each new frame calls `QueueRender` on the main context.
4. `TestPatternSource` frames (smpteBars/fullBars/grid/grayRamp in NV12/YUYV/planar) drive the window through `-testPattern`.
5. Pixel tests: an EGL surfaceless (or pbuffer) context on Mesa in `HDMICaptain.Linux.Media.Tests` renders 75 % bars limited vs full range and checks the pass-1 readback, the same checks as the Windows WARP tests. Geometry agrees with the fixtures.
6. Check that resizing the window letterboxes correctly per scale mode on WSLg, and that WSLg reaches 60 fps (renderer stats).

## Acceptance criteria

- [ ] `make linux-run LINUX_ARGS="-testPattern smpteBars"` shows correct bars in WSLg; fit/fill/stretch/integer behave on resize (screenshots checked, then deleted)

- [ ] Android still builds from the shared sources (`make android-build` on a machine with the SDK), or the fork is logged with the reason
