## Objective

The `AudioPipeline` equivalent: play the card's HDMI audio to the chosen output with low, flat latency, plus delay, channel modes, volume, mute and meters.

## Steps

1. Find the card's capture endpoint by ContainerId (`IMMDeviceEnumerator`, `PKEY_Device_ContainerId`); list other endpoints for manual override.
2. Capture and render clients in shared, event-driven mode; `IAudioClient3.InitializeSharedAudioStream` at the minimum period, falling back to `Initialize`. Both threads under MMCSS "Pro Audio". Resample to the output mix rate when it differs from 48 kHz.
3. Ring buffer + drift controller: hold the fill near the target set by the delay (0–500 ms) by nudging the resample ratio. Log the fill once a second in DEBUG.
4. Channel modes (auto / L↔R swap / mono fix), volume, mute, peak/RMS meters; the MS2109 96 kHz mono reinterpretation from `ms2109-audio.json` (087).
5. Follow the default output (`IMMNotificationClient`) and survive `AUDCLNT_E_DEVICE_INVALIDATED`. `E_ACCESSDENIED` (microphone privacy) raises an event and never stops video.
6. Tests: ring/drift controller with a simulated ±100 ppm clock offset over a simulated hour (fill stays in band), channel maps, MS2109 rule.

## Acceptance criteria

- [ ] HDMI audio from a real card plays through the default output; latency logged (capture → render, ms)
- [ ] Simulated drift test keeps the ring fill within ±10 ms of target over 1 h of virtual time
- [ ] Microphone privacy off → video keeps running and an audio-blocked event fires
