# 059 — UX/UI audit of every screen (Mac + iPad), with Codex review

**Status:** done
**Phase:** Phase 9: Polish & launch readiness
**Depends on:** none
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

Capture every user-visible state on both platforms and get an outside design review from Codex, plus our own, into one prioritised list. The later polish tasks implement this list instead of guessing.

## Relevant files / modules

- `Apps/Shared/ContentView.swift` — overlays: status, no signal, paused, banners, toasts, stats
- `Apps/Shared/ControlBar.swift`, `Apps/Shared/PauseIllustration.swift`, `Apps/Shared/Store/UpgradeView.swift`
- `Apps/macOS/Sources/SettingsView.swift`, `Apps/iPadOS/Sources/SettingsSheet.swift`
- QA hooks: Mac `-qaAction …` + winshot; iPad `make ipad-snapshot`, `-qaAction settings` (CLAUDE.md)
- Codex CLI (`~/.local/bin/codex exec`). The codex-image plugin's `--full-auto` call is broken on 0.153, so call it directly: `codex exec -s workspace-write --skip-git-repo-check -C <dir> "Use the imagegen skill … save to <path>"` for images, and `codex exec -s read-only -i shot.png "…"` for design review

## Steps

1. Screenshot each state on Mac and iPad: scanning, permission needed/denied, connecting, live (bar shown), no signal, paused (iPad), failed, recording, toast, upgrade sheet, Settings (each page), Pro locked. Save them in `docs/research/ux/shots/`. Add DEBUG QA actions for any state that can't be reached on demand.
2. Run a Codex review with the screenshots attached (`-i`). Ask for hierarchy, consistency, Apple HIG fit, copy clarity and accessibility, with concrete fixes.
3. Add our own review and merge both into `docs/research/ux-review.md`: a table of issue, screen, severity (P1/P2/P3), proposed fix, and owning task (060–067 / 048).
4. Update the steps of tasks 061–067 if the review changes their scope.

## Acceptance criteria

- [x] `docs/research/ux/shots/` has every state listed in step 1 for both platforms (or a note saying why one can't be captured)
- [x] `docs/research/ux-review.md` exists, with the Codex findings quoted or summarised and each issue assigned to a task
- [x] No face-revealing captures (privacy rule): only window or app captures
