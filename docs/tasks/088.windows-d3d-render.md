## Objective

The `MetalRenderer` equivalent: YCbCr → RGB on D3D11 into a low-latency flip-model swap chain, driven by generated test patterns so it works without a card. It also establishes whether WinUI's `SwapChainPanel` can reach independent flip.

## Steps

1. `D3DRenderer` on a device created on the adapter of the window's monitor (DXGI output → adapter LUID). Recreate it on `DXGI_ERROR_DEVICE_REMOVED` and when the window moves to another adapter.
2. HLSL compiled at runtime from embedded source (`D3DCompile`, like Metal). Inputs: NV12 (R8 + R8G8 views), YUY2 (RGBA8 at half width), planar 4:2:0/4:2:2/4:4:4 (3× R8, for JPEG), BGRA. Pass 1 converts at source size (BT.601/709, limited/full/auto, adjustments, LUT 3D texture); pass 2 scales (fit/fill/stretch/integer, linear/nearest) and draws guides.
3. Swap chain: `FLIP_DISCARD`, 2 buffers, `FRAME_LATENCY_WAITABLE_OBJECT`, `SetMaximumFrameLatency(1)`, `ALLOW_TEARING` when supported. Present when a frame arrives; skip presents while hidden.
4. Host it in a `SwapChainPanel` (composition swap chain). Also build the alternative HWND swap-chain host behind an `IVideoSurface` interface, so 092 can compare them.
5. `TestPatternSource` produces SMPTE bars, full bars, grid and gray ramp in NV12/YUY2/planar at 1080p60 and 4K30. `-testPattern` selects it.
6. Tests on WARP: render each pattern and compare known pixels (75% bars, limited vs full range) with a tolerance; geometry from the fixture.

## Acceptance criteria

- [ ] `make win-run WIN_ARGS="-testPattern smpteBars"` shows correct bars; window resizes keep the aspect ratio per scale mode
- [ ] WARP pixel tests pass for NV12, YUY2 and planar inputs and both ranges
- [ ] PresentMon output for the panel and the HWND surface, windowed and borderless full screen, is logged in this task (present mode per case)
