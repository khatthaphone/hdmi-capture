# HDMI Captain — Task Plan

## Overview

Build a clean-room native replacement for Dongled (an HDMI-capture viewer) that never disconnects on macOS. Next, expand it with the features the competitor research found missing in the market, under a **free viewer + one-time Pro unlock** model (Pro = recording, replay buffer, streaming, virtual camera). Then add the mini-OBS features and the iPadOS, Android, Windows and Linux versions. Phases 0–2 and 7–8 are broken down to single-sitting tasks. Phases 3–6 are coarser, and some are marked **epic**. Split an epic into smaller tasks before you start it.

**Source material:** `docs/spec.md` (authoritative), `docs/research/ipados.md` (Phase 3), `docs/research/android.md` + spec §12 (Phase 5), `docs/research/windows.md` + spec §13 (Phase 6), `docs/research/linux.md` + spec §14 (Phase 10), `docs/research/competitors.md` (feature expansion), `docs/research/devices/` (real dongle formats) and the existing code in `Packages/CaptureCore` and `Apps/macOS`. Dongled is FairPlay-encrypted and is **not to be decrypted or decompiled**. If this plan and `docs/spec.md` disagree, the spec wins. Update both.

## How to work this plan

Any agent (or human) picking up this plan should follow this loop:

1. **Pick the next task** whose `Status` is `todo` and whose `Depends on` tasks are all `done`. If several qualify, take the lowest ID unless the user says otherwise.
2. **Before starting:** open that task's file, set `Status: in-progress`, and add a dated log entry noting you're starting.
3. **While working:** append short, dated log entries for real decisions or blockers — not a narration of every edit. A future agent (possibly you, in a new session) should be able to read the log and understand what happened without re-reading the whole conversation.
4. **If blocked:** set `Status: blocked`, log why and what's needed to unblock, and surface it to the user rather than guessing past it.
5. **When finished:** verify every item under "Acceptance criteria" is actually true (don't just assume) — check them off, set `Status: done`, and add a completion log entry.
6. **After any status change:** update that task's row in the table below and refresh the progress bar at the top of this file. This file is the source of truth for plan-level progress — a task file changing status without this file being updated means the plan is out of sync.

If requirements shift enough that tasks need to be added, split, or dropped, edit this plan directly (add rows, create new task files, mark obsolete tasks with a note in their log rather than deleting them) — don't silently drift from what's written here.

**Project-specific rules:**
- Never decrypt, dump or decompile Dongled. Copy its behaviour only.
- Several tasks need real hardware: an HDMI dongle and a source. These are 001, 006, 007, 009, 014, 031, 032, 034, 035 and the later spikes. Available: UGREEN HDMI Capture (MS2131, USB 2.0, 720p60/1080p30) and UGREEN-25854 (1080p60), with a Sony a6600 as the source. Phase 3 (iPad) hardware tasks (052–058, 021) also need a **USB-C iPad on iPadOS 17+** (M-series preferred for Stage Manager multitasking camera access) and Xcode wireless debugging, because the card holds the USB-C port. Phase 5 (Android) hardware tasks (072–076, 084) need **≥ 2 Android devices with USB-C host mode** (ideally a Pixel and a Samsung/MediaTek phone) and wireless adb, because the card holds the port. Phase 6 (Windows) hardware tasks (089, 091, 092, 093, 096, 098, 100, 102) run on the **Windows dev PC** (Ryzen 7 9700X, RTX 5070 Ti + Radeon iGPU) with the cards plugged in. Latency tests need a **real monitor**: the Parsec virtual display doesn't count. Build Windows with the .NET 10 SDK (`make win-build`). Phase 10 (Linux) is developed in **WSL2 Ubuntu-24.04 + WSLg on the same PC** (`make linux-*` from Git Bash). The card reaches WSL through usbipd-win, which **takes it away from Windows while attached**, so ask the user before `usbipd attach`. Installing packages and usbipd's one-time `bind` need the user (sudo password / UAC). Linux sign-off (108 live part, 113 suspend, 120 clap test, 121, 124) needs a **real Linux install**; WSLg numbers don't count for latency. Build Android with JDK 21 from Android Studio's JBR, not the system JDK 26. If no hardware is available, set `blocked` and ask the user. Don't fake results.
- **Commit after every finished task** (and at meaningful checkpoints), with the message `NNN: <task title>` and the Co-Authored-By trailer. Run `make build && make test` first (Windows tasks: `make win-build && make win-test`; Linux tasks: `make linux-build && make linux-test`).
- **Pricing rule:** the viewer stays free and unrestricted. Only `ProFeature` items (recording, replay buffer, streaming, virtual camera) are gated, through `EntitlementStore` (042).
