## Objective

Measure what the spikes deliver on real hardware so ADR 0003 can be accepted: glass-to-glass latency per format and surface, present mode, and a 30-minute soak.

## Relevant files / modules

- `docs/spec.md` §13 — Windows requirements
- `docs/research/windows.md` — research (2026-10-22)
- `Packages/CaptureCore/Sources/CaptureCore/LatencyProbe.swift`, `Apps/macOS/Sources/LatencyTest.swift` — the method to port
- `Apps/Shared/QASoak.swift` — soak CSV columns
- Task 035 — how the Mac latency test works

## Steps

1. Port `LatencyProbe`: a flip window on the PC's HDMI output → card → app, timing the detected flip. Needs a **real monitor or HDMI loop**, not the Parsec virtual display.
2. Measure: UGREEN-25854 and MS2131, each at its best uncompressed format and MJPEG (if offered); `SwapChainPanel` vs HWND surface; windowed vs borderless full screen. Record the PresentMon present mode for each.
3. Cross-check one case with a 240 fps phone video against OBS preview and the Windows Camera app on the same card.
4. `-qaSoakMinutes 30` → `Documents\HDMI Captain\qa-soak.csv` (fps, drops, working set, GC count, audio ring fill) at 1080p60.
5. Record results in `docs/research/devices/` and in the ADR 0003 table.

## Acceptance criteria

- [ ] Latency table filled for both cards × surface × windowed/full screen
- [ ] 30-min soak: drops not growing, working set and audio fill flat (CSV committed)
- [ ] A decision recorded on `SwapChainPanel` vs HWND surface for viewer windows
