## Objective

Meet the §14.10 targets on real Linux: steady 60 fps, no per-frame allocation, real-time threads, present on arrival, optional graphics offload, and a stage trace.

## Relevant files / modules

- `docs/spec.md` §14 — Linux requirements
- `docs/research/linux.md` — research (2026-10-23)
- `Apps/Windows` task 101 and the `HDMICaptain-Media` EventSource
- GTK graphics offload: https://blog.gtk.org/2023/11/15/introducing-graphics-offload/

## Steps

1. An EventSource with FrameCaptured/Decoded/Uploaded/Presented, readable with `dotnet-trace`.
2. Allocation audit while live; `GCSettings.LatencyMode = SustainedLowLatency`.
3. rtkit priority verified (`chrt -p`); fallback logged.
4. Try `GtkGraphicsOffload` + `GdkDmabufTextureBuilder` (manual P/Invoke for `Build()`) for full screen; keep it only if latency or CPU measurably improves.
5. ReadyToRun publish; measure startup time on real Linux.

## Acceptance criteria

- [ ] Stage timings logged on real Linux for windowed and full screen
- [ ] No gen0 GC during a 5-min live run
- [ ] The offload decision is logged with numbers
