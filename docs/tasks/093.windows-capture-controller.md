## Objective

The Windows `CaptureEngine`: one control thread that owns discovery, audio pairing, source selection, error mapping and recovery, honouring spec §13.2 and §13.5.

## Steps

1. `DeviceCatalog`: MF enumeration + `CM_Register_Notification`, stable key (VID:PID + serial/name), ContainerId audio pairing, remembered preferred device.
2. `CaptureController` on a single control thread driving `RecoveryMachine` (087): open → first frame → Live; watchdog for no signal / no frames; errors → InUse / PrivacyBlocked / Recovering with backoff; unplug → switch to another plugged card or Scanning.
3. Power and scheduling: a `PowerRequestDisplayRequired` request while live, EcoQoS opt-out, MMCSS on capture/decode threads, `RegisterSuspendResumeNotification` → rebuild.
4. Never stop for minimize, occlusion, focus loss or virtual-desktop switches; the viewer just skips presents.
5. Tests with fake sources and virtual time: privacy denied, in use then released, unplug mid-stream, replug, sleep/resume, preferred card returns.

## Acceptance criteria

- [ ] Unplug/replug, another app taking the card then releasing it, and sleep/resume recover without user action (log)
- [ ] Minimize / occlude / virtual-desktop switch for 5 min → no capture restart in the log
- [x] Controller tests cover every state transition listed above
