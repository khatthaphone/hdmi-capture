- 2026-10-23 — **Audio underflow cycle fixed (091 code, found here).** The new per-second log showed the mechanism: capture packets and render periods are both 480 frames (10 ms); when a packet lands just after a render read, the fill at that read is a whole packet below its mean, and with a 20 ms mean that left 479 frames for a read needing 483 (480 + resampler look-ahead). The clocks drift, so the phase crosses that point every ~9.3 min, and each crossing also made the raw fill reading jump by a packet, which the PI loop chased (ratio +263 ppm, draining) before refilling. Fixes: the fill target is at least capture packet + render period + 2 ms (`DriftController.MinimumTargetMs`, 22 ms on this card, plus the user delay), and the loop sees a phase-free fill (ring fill + audio arrived since the last packet, at most one packet; `PhaseFreeFillFrames`). With the floor alone: 27 min, 0 underflows, lowest read-time fill 483 frames (zero margin, at a crossing). With both: see next entry. Grid tile chips now use the overlay theme brushes (094 high contrast).
