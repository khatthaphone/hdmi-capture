# 090 — MJPEG decode: libjpeg-turbo to planar YUV, benchmarked

**Status:** done
**Phase:** Phase 6: Windows
**Depends on:** 088
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

Decode MJPEG frames fast enough for 1080p60 (and 4K30 on this PC) straight to YCbCr planes that the renderer converts on the GPU.

## Relevant files / modules

- `docs/spec.md` §13 — Windows requirements
- `docs/research/windows.md` — research (2026-10-22)
- `Apps/Android/core/render/` — the Android libjpeg-turbo decoder (074) to mirror
- `docs/research/windows.md` §3

## Steps

1. `MjpegDecoder` over `turbojpeg.dll` (P/Invoke, `tj3DecompressToYUV8` into pooled native plane buffers), with N worker decoders where the newest frame wins and stale frames are dropped, never queued.
2. Handle 4:2:2 and 4:2:0 JPEG subsampling and full-range JPEG YCbCr (set the renderer's range from the JPEG, not the UVC descriptor).
3. Probe optional fast paths and log them: DXVA MJPEG decoder profile on each adapter (RTX 5070 Ti, Radeon iGPU) and the MF MJPEG MFT. Don't use them yet; record the results for the ADR.
4. Benchmark with sample frames (`ffmpeg -f lavfi -i testsrc2=size=1920x1080:rate=60 -c:v mjpeg` plus a captured MS21xx frame once 089 runs): p50/p95 ms per frame at 1080p and 2160p, 1 vs 2 threads.
5. Tests: decode fixture JPEGs (4:2:0, 4:2:2) and compare plane checksums.

## Acceptance criteria

- [x] 1080p MJPEG decodes at p95 < 8 ms with 2 threads on this PC (numbers in the log)
- [x] Probe results for DXVA MJPEG on both GPUs recorded in this log
- [x] Decoder tests pass in `make win-test`
