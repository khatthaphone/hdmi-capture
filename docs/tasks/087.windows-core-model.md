## Objective

C# ports of the platform-free logic, tested against the same `docs/fixtures/` vectors as Swift and Kotlin, so all three behave the same.

## Relevant files / modules

- `docs/spec.md` §13 — Windows requirements
- `docs/research/windows.md` — research (2026-10-22)
- `docs/fixtures/README.md` — fixture formats
- `Packages/CaptureCore/Sources/CaptureCore/FormatSelector.swift`, `SignalAnalyzer.swift`, `Presets.swift`, `Profiles.swift`, `CubeLUT.swift`, `Entitlements.swift`
- `Apps/Android/core/model/` — Kotlin ports, especially `RecoveryMachine` and the bandwidth rule
- `Apps/Shared/Model/ViewerPrefs.swift` — prefs keys

## Steps

1. Port `FormatSelector` (auto + pinned + the link-bandwidth rule from Kotlin), `RecoveryMachine` + backoff, `SignalAnalyzer`/`SignalMonitor`, `RenderGeometry`, `CubeLUT` parser, `ProFeature`, presets/profiles/prefs models (System.Text.Json source-generated, the same keys as `ViewerPrefs`).
2. Map MF subtypes to fixture fourCCs (`MJPG`, `YUY2`, `NV12`) in one place.
3. xUnit tests read every shared fixture from `docs/fixtures/` (path relative to the repo root). Add Windows rows to `docs/fixtures/README.md`.
4. Add `ms2109-audio.json`: the endpoint formats that trigger the 96 kHz mono → 48 kHz stereo reinterpretation, and those that don't. Read it from C# (and from Swift later, if the Mac adds the rule).
