## Objective

Consistent, friendly, short wording everywhere: overlays, toasts, menus, settings labels and footers, upgrade sheet, errors. Write the voice down so future features match.

## Relevant files / modules

- `grep -rn 'Text("\|Label("\|showToast(\|onMessage?(' Apps/` — the string inventory
- `Packages/CaptureCore/Sources/CaptureCore/CaptureEngine.swift` — engine reasons that reach the UI (recovering, PauseReason)
- Apple HIG Writing guidelines; design:ux-copy skill

## Steps

1. Inventory every user-facing string into `docs/copy.md` (string, where, current → proposed).
2. Write the voice rules at the top of `docs/copy.md`: plain words, sentence case for messages, title case for menu items (macOS), no blame, say what to do next, "capture card" not "dongle", "Save Recent" naming.
3. Apply the proposed strings. Keep technical stats `verbatim`.
4. Make sure engine errors shown to users are human (e.g. "lockForConfiguration failed" never surfaces).

## Acceptance criteria

- [x] `docs/copy.md` exists with the voice rules and the full inventory
- [x] No user-facing string uses "dongle", raw error codes or developer jargon (grep check documented in the log)
- [x] Both apps build and the screenshots in ux/shots are updated for the changed screens
