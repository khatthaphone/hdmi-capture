# 052 — iPadOS capture-card discovery & hot-plug

**Status:** done
**Phase:** Phase 3: iPadOS
**Depends on:** 049
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

Make `AVDeviceProvider`/`DeviceCatalog` find capture cards on iPadOS (`.external` video + the single `.microphone` audio device), and handle the iPadOS rule that a reconnected card is a **new** `AVCaptureDevice`, possibly with a new `uniqueID`.

## Relevant files / modules

- `Packages/CaptureCore/Sources/CaptureCore/AVDeviceProvider.swift` — discovery session device types; hot-plug observers (incl. the 1 s/3 s re-check added for the macOS race)
- `Packages/CaptureCore/Sources/CaptureCore/DeviceCatalog.swift` — audio pairing (`usbIDs(from: modelID)`); on iOS the audio side is one `.microphone` device, so pairing becomes "is the current input route `.usbAudio`"
- `Packages/CaptureCore/Sources/CaptureCore/Presets.swift` — keyed by `uniqueID`; needs a stable fallback key (modelID + name)
- `docs/research/ipados.md` — platform facts and sources for this phase

## Steps

1. Under `#if os(iOS)`, discover with `[.external]` for video, and `.microphone` for audio.
2. Pair audio on iOS: treat the `.microphone` device as the card's audio when `AVAudioSession.currentRoute.inputs` contains a `.usbAudio` port. Otherwise report "no card audio" rather than silently using the built-in mic.
3. Key presets and profiles by a stable identity (modelID + localizedName) when `uniqueID` changes across reconnects. Add unit tests for the key derivation with a fake provider.
4. Hot-plug: observe `wasConnected`/`wasDisconnected` and KVO the discovery session's `devices`. Hop to the catalog's queue because notifications arrive on background queues.
5. Add `DeviceCatalog` tests for the iOS pairing rules with a fake provider (no hardware).

## Acceptance criteria

- [x] New unit tests pass via `make test-ios-core` and `make test`
- [x] On a USB-C iPad with a card: plugging the card in while the app runs shows it within 3 s, and unplug/replug brings the picture back with the same preset applied (**hardware**)
- [x] When the card has no audio route, the UI says so instead of playing the built-in mic
