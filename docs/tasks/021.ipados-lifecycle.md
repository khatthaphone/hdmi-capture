# 021 — iPadOS lifecycle, multitasking & Stage Manager

**Status:** done
**Phase:** Phase 3: iPadOS
**Depends on:** 053
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

iPadOS forbids the camera in the background (`videoDeviceNotAvailableInBackground`). Disabling it in Split View, Slide Over and Stage Manager is only the default, and multitasking camera access can lift it. Make both cases graceful, so we fix the iPad version of the Dongled problem as far as the OS allows: keep the session configured, resume instantly, and keep video running beside other apps where the device supports it.

## Relevant files / modules

- `Packages/CaptureCore/Sources/CaptureCore/CaptureEngine.swift` — interruption handling and always-on recovery (007); **don't call `stopRunning` on background**, because the session restarts itself
- `Apps/iPadOS/Info.plist` — `UIRequiresFullScreen=false`
- `docs/research/ipados.md` — platform facts and sources for this phase

## Steps

1. On iOS observe `AVCaptureSession.wasInterruptedNotification`/`interruptionEndedNotification`, and map the reasons to UI states ("Paused — HDMI Captain is in the background", "Camera unavailable while multitasking on this iPad").
2. Set `session.isMultitaskingCameraAccessEnabled = isMultitaskingCameraAccessSupported` before `startRunning`. **Don't** add the `voip` background mode (App Review risk).
3. On return: keep the last frame on screen until the first new frame arrives, so there's no black flash. Measure the time to the first new frame.
4. Stage Manager: the window resizes freely, and the picture, bar and HUD lay out at every size.
5. Interaction with recording and Save Recent: finalise or pause cleanly on interruption, and keep the Save Recent buffer when possible.
6. Log every interruption reason, so 058 can check them.

## Acceptance criteria

- [x] Background → foreground restores the live picture in < 500 ms, with no black flash (**hardware**, measured from the log)
- [x] In Stage Manager on a supported iPad, video keeps running while another app is frontmost beside it (**hardware**). On an unsupported iPad, the paused state names the reason
- [x] Recording interrupted by backgrounding leaves a playable file
