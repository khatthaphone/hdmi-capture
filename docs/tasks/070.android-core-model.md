# 070 — Port pure logic to `:core:model` with shared JSON fixtures

**Status:** done
**Phase:** Phase 5: Android
**Depends on:** 069
**Complexity:** complex — suggested model: Claude Code → sonnet · Codex → terra

## Objective

Port the platform-free logic from CaptureCore to Kotlin with the same names, and make Swift and Kotlin tests read the same JSON fixtures so behaviour can't drift.

## Relevant files / modules

- `docs/spec.md` §12 — Android requirements
- `docs/research/android.md` — research
- `Packages/CaptureCore/Sources/CaptureCore/FormatSelector.swift`
- `CaptureEngine.swift` — `CaptureState`, `PauseReason`, backoff
- `SignalAnalyzer.swift`, `Presets.swift`, `Profiles.swift`, `CubeLUT.swift`
- `docs/research/devices/*.json` — real card formats

## Steps

1. Create `docs/fixtures/` with format-choice vectors (from the device JSONs, plus synthetic MJPEG/USB 2.0 cases), signal-classifier stats vectors and recovery event sequences.
2. Kotlin `FormatSelector` incl. link-speed bandwidth rule (spec §12.3); `CaptureState` sealed interface + `RecoveryMachine` (events → state, backoff 0.25 s → 4 s); `SignalAnalyzer.classify`; preset/profile models with the stable key; `.cube` parser.
3. Swift tests in CaptureCore read the same fixtures for FormatSelector and SignalAnalyzer (add, don't replace existing tests).
4. Kotlin unit tests read the fixtures.

## Acceptance criteria

- [x] `make test` (Swift) and `make android-test` (Kotlin) both pass over the same fixture files
- [x] `:core:model` has no Android dependency (plain JVM module)
- [x] USB 2.0 + 1080p60 fixture picks MJPEG; USB 3 picks uncompressed
