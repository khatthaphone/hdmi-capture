# HDMI Captain — UI copy guide

Voice rules first, then an inventory of every user-facing string (generated by grep; refresh it after
copy changes with the snippet in task 063's log). Technical diagnostics (stats overlay) are
`Text(verbatim:)` and not localized.

## Voice

1. **Plain words, short sentences.** Say what happened, then what to do: "No HDMI signal. Check that the source is on and the HDMI cable is plugged in."
2. **Never blame** the user and never show raw errors or codes. Technical detail goes in a small secondary line at most.
3. **Name things the same everywhere:** *capture card* (never "dongle" or "device" in UI), *source* (console or camera), *HDMI signal*, *Save Recent* / *Keep Recent Footage*, *Pro*, *diagnostics* (not "stats").
4. **Case:** title case for menu items, buttons and Mac Settings section titles ("Save Screenshot", "Keep Recent Footage"); sentence case for messages, toggles and footers ("Show controls near the bottom edge").
5. **Feedback kinds** (`Feedback.Kind`): success is past tense ("Screenshot saved"); warning says how to make it work ("Connect a capture card to record"); errors start with "Couldn't…" or "Can't…" plus the reason.
6. **Pro:** honest and specific. Only shipping features, "One-time purchase. No subscription.", and the free viewer is always mentioned.
7. **iPad vs Mac:** use `StatusCopy.device` ("Mac" / "iPad"); system paths differ (System Settings › Privacy & Security › Camera vs Settings).
8. **Ellipsis** (…) only on commands that open a further step (Settings…, Choose .cube File…) and on ongoing work ("Connecting to UGREEN-25854…").
